# 第四阶段：游客语音输入

更新时间：2026-07-16

## 阶段目标

在“黄山知识库 + Dify RAG + 导游语音播报”的基础上，为游客端增加浏览器语音输入能力。

当前实现使用浏览器原生 Web Speech Recognition。游客点击麦克风后，说出问题，页面会把识别结果填入输入框；开启“识别后发送”后，最终识别结果会自动提交给后端。

## 已实现功能

- 输入框旁边新增麦克风按钮。
- 支持中文语音识别，语言设置为 `zh-CN`。
- 识别中的临时文本会显示在输入框中。
- 顶部新增“识别后发送”开关。
- 麦克风权限拒绝、未检测到语音、浏览器不支持等情况会显示友好提示。
- 不支持语音识别时，文字输入和 Dify 问答仍然可用。

## 使用方式

启动后端：

```powershell
cd /d D:\ai-scenic-guide\services\api-server
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动前端：

```powershell
cd /d D:\ai-scenic-guide\apps\visitor-web
npm.cmd run dev
```

打开：

```text
http://localhost:5173/
```

点击输入框右侧的麦克风按钮，允许浏览器使用麦克风，然后说出问题。

## 验收问题

- 黄山为什么叫黄山？
- 黄山一日游路线怎么走？
- 从黄山北站怎么去黄山风景区？
- 西海大峡谷适合老人走吗？

## 浏览器与设备注意事项

Web Speech Recognition 在 Chrome 和 Edge 上支持较好。正式部署到景区设备前，需要在目标触摸屏、平板或一体机上验证：

- 浏览器是否支持语音识别。
- 麦克风权限是否可用。
- 现场噪声是否影响识别准确率。
- 是否需要外接定向麦克风。
- 全屏模式下是否仍能弹出麦克风权限。

如果后续需要更稳定的生产级 ASR，可将浏览器识别替换为讯飞、阿里云、火山引擎或本地离线 ASR 服务。前端麦克风控件和交互流程可以继续复用。
